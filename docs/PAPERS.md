| ZSON: Zero-Shot Object-Goal Navigation using Multimodal Goal Embeddings | **2022** (281) | The key new move is a “train-on-ImageNav, deploy-on-ObjectNav” zero-shot transfer enabled by CLIP-aligned goal embeddings: they train a goal-conditioned navigator only with goal images (ImageNav) and then, at test time, swap the goal encoder input from an image to a text prompt (e.g., “chair”) to do ObjectNav without any ObjectNav rewards, trajectories, or fine-tuning. | RL (DD-PPO) + multimodal (CLIP) goal embeddings; recurrent policy (2-layer LSTM); pretrained visual encoder (ResNet-50 via DINO/OVRL recipe). | ObjectNav: Gibson, HM3D (Habitat 2022), MP3D (Habitat 2020); also ImageNav (Gibson), all in Habitat. | Can inherit dataset priors (e.g., “stove→kitchen”) and struggle when targets appear in unusual contexts; zero-shot to ObjectNav but still needs large-scale ImageNav training/compute; RGB-only can hurt path efficiency vs depth-based heuristics. | Architecture: RGB → pretrained ResNet-50; concat with goal embedding (1024-d CLIP) + prev-action embedding → 2-layer LSTM policy. | OVRL-V2: A simple state-of-art baseline for IMAGENAV and OBJECTNAV | **2023** (93) | A single model-free ViT+LSTM navigator (no detectors/segmentors/maps/planners) can reach SoTA on ImageNav and strong ObjectNav if you (i) preserve spatial structure from ViT patches via a compression layer, and (ii) use in-domain SSL pretraining (e.g., MAE) plus a few policy-training recipe fixes. It is task-agnostic! |Transformer backbone (ViT) + conv “compression layer” + LSTM; RL (DD-PPO) for ImageNav; imitation learning / behavior cloning from human demos for ObjectNav; in-domain SSL pretraining (MAE/Data2Vec).| Habitat simulator. ImageNav: Gibson benchmark (72 train / 14 val) from prior work. Shows positive scaling (ViT-S→ViT-B) only after in-domain SSL pretraining and LR tuning; reports ~82% SR on ImageNav and ~64% SR on HM3DSEM ObjectNav test-standard with RGB-only.
| PIRLNav: Pretraining with Imitation and RL Finetuning for ObjectNav | **2023** (137) | Pretrain an ObjectNav policy with behavior cloning on human demos, then RL-finetune with sparse success reward; use a staged finetuning scheme (critic-first, then actor+critic) to avoid early destructive updates from an untrained critic.| Imitation learning (BC + inflection weighting) → on-policy RL finetuning (DD-PPO / PPO); recurrent CNN+RNN (ResNet-50 + 2-layer 2048-d GRU); visual SSL pretraining (DINO on Omnidata) + RGB aug.| Habitat simulator; HM3D-Semantics v0.1 with Habitat ObjectNav Challenge 2022 train/val/test splits (6 goal categories, 500-step episodes). Sensors include RGB + GPS/Compass (depth available but they report not using it). | Still depends on costly human demonstrations for best results (they collect ~77k); RL finetuning is compute-heavy (hundreds of millions of steps) and still uses GPS/Compass; common remaining failures are inter-floor navigation and object recognition/last-mile issues, plus dataset/navmesh noise. | Main technical contribution is the BC→RL finetuning recipe: (1) freeze the BC policy and train critic-only on rollouts until stable, then (2) warm up actor LR while decaying critic LR before joint training. This lets PPO work even with sparse rewards, beating prior finetuning baselines (e.g., VPT-style) and reaching ~65% success / 33% SPL on HM3D test (Challenge 2022). They also show human demos produce better downstream RL generalization than “free” demos (shortest-path/frontier exploration), and quantify diminishing returns as demo count increases; their failure-mode breakdown highlights dataset issues + stairs/inter-floor as major bottlenecks.
| Can an Embodied Agent Find Your “Cat-shaped Mug”? LLM-Based Zero-Shot Object Navigation (LGX) | **2023** (179) | Proposes **Language-Guided Exploration (LGX)** for language-driven zero-shot object navigation: use an **LLM’s commonsense** to choose exploration directions/subgoals from scene semantics, while an **open-vocabulary grounding model** searches for the free-form described target. | LLM-guided exploration (GPT-3 prompting) + open-vocab grounding (GLIP); classical mapping/planning (RTAB-Map costmap + ROS move_base); no RL training for navigation policy. | **Simulation:** RoboTHOR validation set (15 envs, 1800 episodes, 12 goal categories). **Real world:** TurtleBot 2 two-phase “room→hallway→room” experiments with uniquely described objects. | Heavy dependence on **engineered loop + thresholds** (rotate-in-place each step, GLIP confidence threshold Gth, max turns nr); prompt sensitivity can cause loops or invalid outputs; requires **depth + mapping stack** (costmap) and assumes reliable perception/SLAM; RoboTHOR may be a skewed benchmark for “intelligent” exploration. | Pipeline: at each step do a **360° rotation** to collect RGB+depth; extract semantics via **YOLO object list** or **BLIP captions**; synthesize a prompt and query GPT-3 for an object/direction; move using costmap planning; run **GLIP** in parallel to detect the described target and stop when confidence exceeds Gth. | OpenFMNav: Towards Open-Set Zero-Shot Object Navigation via Vision-Language Foundation Models | **2024** (71) | Turns ObjectNav into **free-form instruction following** (including implicit demands) and achieves **open-set, zero-shot** navigation by using an LLM to propose/interpret goals and reason about where to explore, while a VLM builds a continuously updated semantic map from detected/segmented objects. | Foundation-model modular pipeline: **LLM reasoning** (ProposeLLM + ReasonLLM, GPT-4) + **VLM discovery** (GPT-4V) + **open-vocab detection/segmentation** (Grounded-SAM = GroundingDINO+SAM) + mapping (VSSM) + classical planning/control (FMM).| **Simulation:** Habitat **HM3D ObjectNav** validation (80 train / 20 val scenes; eval on 20 val; **2000 episodes**, 6 goal classes). **Real robot demos:** TurtleBot4 + Kinect RGB-D in offices/labs/meeting rooms with open-set goals (e.g., “robot arm”). | Needs **accurate depth + pose** to build the 2D map; depends on **internet/API access** and can have **latency** from LLM/VLM calls; performance hinges on perception quality and can mis-detect or time out during exploration.| Key object memory is a **Versatile Semantic Score Map (VSSM)**: multi-channel top-down map storing **confidence scores** (not binary labels) and dynamically expanding channels as new objects are discovered. | HM3D-OVON: A Dataset and Benchmark for Open-Vocabulary Object Goal Navigation | **2024** (55)| Introduces **HM3D-OVON**, a large-scale **open-vocabulary** ObjectNav benchmark on photorealistic 3D scans, where goals are **free-form text** and evaluation explicitly tests generalization to **seen / synonym / unseen** object categories. | Dataset + benchmark with baseline suite: end-to-end **IL** (BC, DAgger), **RL** (PPO), **IL→RL** (BCRL, DAgRL), and **modular** (VLFM; plus DAgRL+OD).| Habitat on **HM3D-Sem** scans: 181 scenes, **379 categories**, 15,661 object instances; train/eval scenes disjoint (145/36). Agent spec matches **Stretch** (RGB-D + odometry in task definition; 500-step episodes). | Still **simulation-only** and indoor-household focused; episode generation excludes cross-floor goals (same-floor constraint) and filters for visibility/size (≥5% view from some viewpoint), which may bias difficulty; strong modular baselines can leverage detector priors that aren’t controlled for.| Baseline takeaways: (1) **DAgger + frontier exploration trajectories + sparse-reward RL finetuning (DAgRL)** is the strongest pure end-to-end learner, but drops notably on synonyms/unseen; (2) **open-vocab detection** (OWLv2) stabilizes generalization—**DAgRL+OD** beats VLFM across splits; (3) **transformers > RNNs** for history encoding, and **frontier exploration > shortest-path** demos on HM3D (contradicting SPOC-style findings); (4) RGB-only DAgRL+OD is **more robust to odometry/actuation noise** than map-heavy VLFM. |
| Open scene graphs for open-world object-goal navigation (OSG Navigator) | **2025** (20) | Builds an **open-world ObjectNav** system by using an **Open Scene Graph (OSG)** as persistent spatial memory that lets foundation models (VLMs + LLM) organize semantics for search; schemas let it adapt **zero-shot** to new environment types. | Modular neuro-symbolic pipeline using foundation models: VLM perception (GroundingDINO + BLIP-2), LLM reasoning (GPT-3.5) + structured OSG memory, and a pretrained general navigation model (ViNT) for image-goal local control (no ObjectNav-specific RL/IL training). | **Simulation:** Habitat with **HM3D-Semantics v0.1** (20 val scenes; 400 episodes) and **Gibson** tiny-split val (5 scenes; 1000 episodes). **Real world:** Fetch + Boston Dynamics Spot in an open-plan studio apartment; tests open-vocabulary goals like “guitar” and “dish washer”. | Topo-semantic memory **doesn’t model metric geometry explicitly** (path efficiency limited vs metric planners); relies on multiple large foundation models (latency, API dependence, hallucination/perception errors); evaluated **indoors** only; schema generation and mapping quality hinge on VLM/LLM reliability. | Core design: OSG nodes (Objects/Places/Connectors/Region abstractions) + edges (proximity/connectivity/inclusion/hierarchy). Mapper incrementally builds the graph from RGB using VLM outputs, with LLM-based data association and place recognition; Reasoner queries the LLM to pick promising regions/objects then runs graph search; Controller executes via ViNT on image crops as subgoals. Reports strong training-free SR on HM3D/Gibson and shows gains from structured OSG memory vs list-based LLM baselines (LGX/LFG). |
| CogNav: Cognitive Process Modeling for Object Goal Navigation with LLMs | **2025** (26) | Models ObjectNav as a **human-inspired cognitive process**: an LLM schedules transitions among **fine-grained search/verification states** using an online-built “cognitive map” that summarizes what the agent has seen. This replaces fixed heuristics (or implicit rollout learning) with **LLM-driven state selection**.| LLM/VLM-driven modular navigation (no policy RL/IL training): open-vocab perception + LLM reasoning over a finite-state controller + classical planning (FMM). | **HM3D val** (20 scenes, 2K episodes, 6 categories), **MP3D val** (11 scenes, 1.8K episodes, 20 categories), **RoboTHOR val** (15 envs, 1.8K episodes, 12 categories); also real-robot demos (wheeled robot + Unitree quadruped).| Relies on open-vocab detection/segmentation—if the foundation model misses the target repeatedly, the agent can fail within the time budget; assumes **posed RGB-D** for mapping; doesn’t handle free-form language instructions beyond object-goal text; multi-model stack adds latency/cost. | Key design: a **5-state FSM** (Broad Search, Contextual Search, Observe Target, Candidate Verification, Target Confirmation) where an LLM chooses the next state from landmark-centered prompts derived from a heterogeneous map (scene graph + landmark graph + occupancy map), and can also **correct/update** map content via prompting. Reports SR/SPL: **72.5/26.2 (HM3D)**, **46.6/16.1 (MP3D)**, **54.6/24.3 (RoboTHOR)**, with SR gains vs prior LLM+map baselines; ablations show each state contributes (e.g., removing Candidate Verification increases SPL but drops SR). |
